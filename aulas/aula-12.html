Mini Cadastro com SQLite

Quatro arquivos, um banco que nasce sozinho e o caminho até o CRUD completo.

Objetivo do dia

Montar o Mini Cadastro: listar, cadastrar e excluir clientes num banco SQLite, com o PHP no Apache do XAMPP.

Antes da aula

Ter o XAMPP. Não precisa ter terminado as aulas anteriores: o projeto recomeça do zero.

Como conta ponto

Atividade no laboratório, enviada ao GitHub por upload.

C1–C3 · conceitos

Três ideias, e só

C1

Quatro arquivos, cada um com um trabalho

É o MVC do restaurante, só que enxuto. Cada arquivo faz uma coisa só: deu problema, você já sabe onde procurar.

  • index.html: a porta do restaurante. Só HTML.
  • cadastro.php: o garçom (controle). Recebe o pedido e leva a resposta.
  • banco.php: a cozinha (modelo). O único que fala com o banco.
  • tela.php: o prato (visão). Só mostra.

O caminho de um clique: você abre o cadastro.php → ele pede os clientes ao banco.php → recebe a lista → entrega para a tela.php mostrar.

1cadastro-clientes/2    index.html        // a porta: a página inicial3    cadastro.php      // o garçom: o controle4    banco.php         // a cozinha: o modelo (todo o SQL)5    tela.php          // o prato: a visão (o HTML)6    teste.php         // confere o ambiente7    cadastro.sqlite   // o banco: nasce sozinho
C2

O SQL do CRUD

O banco é uma tabela, como uma planilha: cada linha é um cliente, cada coluna é um dado (id, nome, email).

CRUD são as quatro coisas que todo sistema faz com os dados: Criar, Ler (Read), Atualizar (Update) e Apagar (Delete). Cada uma tem o seu comando, e todos moram no banco.php.

1// C: cria (cadastra) um cliente2INSERT INTO clientes (nome, email) VALUES ('Ana Souza', 'ana@email.com')3// R: lê (lista) os clientes4SELECT id, nome, email FROM clientes ORDER BY nome5// U: atualiza (edita): fica para a aula 146UPDATE clientes SET email = 'ana@novo.com' WHERE id = 17// D: apaga (exclui) um cliente8DELETE FROM clientes WHERE id = 1
C3

prepare: o dado vai separado do comando

Nunca cole o que o usuário digitou dentro do SQL. Com o prepare, o comando vai com um marcador (:nome) e o dado vai separado, no execute.

Por quê? Sem o prepare, alguém digita um pedaço de SQL no formulário e o banco obedece. Esse ataque se chama SQL injection.

1// 1. o comando, com os marcadores :nome e :email2$stmt = $pdo->prepare('INSERT INTO clientes (nome, email) VALUES (:nome, :email)');34// 2. os dados, separados5$stmt->execute([':nome' => $nome, ':email' => $email]);

T1 · tutorial

Mão na massa: o Mini Cadastro em 3 versões

Cada versão é o projeto inteiro, pronto para copiar. Faça uma de cada vez: copie, salve, recarregue o navegador, leia o "entenda o código" e só depois passe para a próxima.

Para refazer em casa: este passo a passo serve do zero, em qualquer computador com o XAMPP. Seu projeto também fica no GitHub: Code › Download ZIP e ele volta inteiro.

Antes de começar

Ligue o Apache e teste o ambiente

Faça assim:

  1. Abra o XAMPP Control Panel e clique em Start na linha do Apache. O MySQL não precisa: o SQLite é um arquivo.
  2. Crie a pasta C:\xampp\htdocs\cadastro-clientes. Já tem a pasta cadastro-clientes da aula 11? Mova ela para dentro do htdocs: a faxina dos arquivos antigos fica para o fim.
  3. Abra a pasta no VS Code (Arquivo › Abrir pasta) e crie o index.html e o teste.php com o código das abas.
  4. No navegador, abra http://localhost/cadastro-clientes/teste.php.

Apareceu "SQLite: DESLIGADO"? É o problema mais comum quando entra o banco. Resolva assim:

  1. No XAMPP Control Panel, na linha do Apache, clique em Config › PHP (php.ini).
  2. Procure (Ctrl + F) por pdo_sqlite. Se a linha for ;extension=pdo_sqlite, apague o ; do começo. Faça o mesmo com ;extension=sqlite3.
  3. Salve, clique em Stop e depois em Start no Apache, e recarregue o teste.php.

Apareceu "PHP DESATUALIZADO"? Esse XAMPP tem a falha PHP2Shell (veja o caso de uso). No laboratório, avise a professora. Em casa, baixe o XAMPP novo em apachefriends.org.

entenda o código

O que o teste.php confere

teste.php

  1. PHP_VERSION é a versão do PHP do seu XAMPP. O version_compare compara com a primeira versão corrigida do PHP2Shell.
  2. extension_loaded('pdo_sqlite') responde se o PHP sabe falar com o SQLite.
  3. Os dois aparecem na tela como sim ou não. Use este teste em qualquer computador, antes de começar.
GitHub por upload

Como enviar o projeto, sem comandos

Faça assim (uma vez agora, e depois de cada versão):

  1. Entre em github.com com a sua conta.
  2. Abra o repositório cadastro-clientes. Não tem? Clique em New, dê esse nome, marque Public e clique em Create repository.
  3. Clique em Add file › Upload files. No repositório vazio, clique no link uploading an existing file.
  4. Arraste os arquivos da pasta para a página. Nunca arraste o cadastro.sqlite: dado de cliente não vai para o GitHub.
  5. Em Commit changes, escreva uma mensagem curta do que mudou e clique no botão verde Commit changes.

Mandou um arquivo com o mesmo nome? O GitHub troca pelo novo e guarda o antigo no histórico (History). Nada se perde.

Envie agora o index.html e o teste.php, com a mensagem Página inicial e teste do ambiente.

Versão 1 · R de Read

O banco nasce e a lista aparece

O banco.php cria a tabela e põe dois clientes de exemplo. O cadastro.php pede a lista e chama a tela.php.

Faça assim:

  1. Crie o banco.php, o cadastro.php e o tela.php com o código das abas. Se já existirem da aula 11, troque todo o conteúdo.
  2. Abra http://localhost/cadastro-clientes/ e clique em Abrir o cadastro: a Ana e o Bruno aparecem.
  3. Olhe a pasta: o arquivo cadastro.sqlite apareceu sozinho. É o banco.
entenda o código

Versão 1, linha a linha

banco.php

  1. new PDO('sqlite:' . __DIR__ . '/cadastro.sqlite') abre o banco. __DIR__ é a pasta deste arquivo. Se o cadastro.sqlite não existe, o PHP cria.
  2. ERRMODE_EXCEPTION: se o SQL tiver um erro, o PHP mostra o erro em vez de ficar quieto.
  3. CREATE TABLE IF NOT EXISTS cria a tabela só na primeira vez. O id se numera sozinho (AUTOINCREMENT).
  4. COUNT(*) conta os clientes. Se der zero, o INSERT põe a Ana e o Bruno, para a lista não começar vazia.
  5. listarClientes() faz o SELECT e devolve um array. Cada cliente é um array com as chaves 'id', 'nome' e 'email'.

cadastro.php

  1. require traz as funções do banco.php para cá.
  2. $clientes = listarClientes();: o garçom pede a lista à cozinha.
  3. require __DIR__ . '/tela.php' chama a visão. Ela enxerga a variável $clientes.

tela.php

  1. <?= ... ?> é o atalho de <?php echo ... ?>: escreve um valor no meio do HTML.
  2. count($clientes) mostra quantos clientes há.
  3. foreach repete o <li> uma vez para cada cliente.
  4. htmlspecialchars impede que um nome com código HTML bagunce a página. É segurança.

Funcionou? Envie para o GitHub: Add file › Upload files, arraste o banco.php, o cadastro.php e o tela.php, escreva Versão 1: lista de clientes e clique em Commit changes.

Versão 2 · C de Create

O formulário cadastra

A tela.php ganha o formulário. O cadastro.php confere os dados e manda gravar. O banco.php ganha o inserirCliente().

Faça assim:

  1. Troque o conteúdo dos três arquivos .php pelo das abas (a etiqueta "mudou" mostra quais).
  2. Cadastre alguém. Depois tente um nome curto e um e-mail sem arroba: o aviso aparece.
entenda o código

Versão 2, o que mudou

tela.php

  1. O <form method="post"> não tem action: ele envia para a própria página, o cadastro.php.
  2. O name de cada campo vira a chave no PHP: name="nome" chega como $_POST['nome'].
  3. <?php if ($erro): ?> só mostra o aviso vermelho quando existe um erro.

cadastro.php

  1. $erro = '': a página começa sem erro.
  2. $_SERVER['REQUEST_METHOD'] === 'POST' quer dizer "o formulário foi enviado". Abrir a página pelo link é GET, e aí nada é gravado.
  3. trim tira os espaços das pontas. O ?? '' evita erro se o campo não veio.
  4. A conferência: nome com menos de 3 letras (strlen) ou e-mail inválido (filter_var) vira aviso.
  5. Deu certo? inserirCliente() grava, e o header('Location: cadastro.php') recarrega a página limpa. Assim, o F5 não cadastra a mesma pessoa duas vezes. O exit para o PHP ali.

banco.php

  1. inserirCliente() é o C do CRUD: o INSERT com prepare e os dados separados, no execute (veja a C3).

Funcionou? Envie para o GitHub: Add file › Upload files, arraste de novo os três arquivos .php, escreva Versão 2: cadastrar e clique em Commit changes.

Versão 3 · D de Delete

O botão Excluir

Cada cliente ganha um botão. O banco.php apaga pelo id, o número que o banco deu ao cliente.

Faça assim: troque os três arquivos .php e exclua um cliente de teste. Não deu tempo na aula? Termine em casa, com o "entenda o código".

entenda o código

Versão 3, o que mudou

tela.php

  1. Cada cliente ganha um formulário pequeno, com um botão só.
  2. O botão tem name="excluir" e value igual ao id do cliente. Clicou, chega $_POST['excluir'] com esse número.

cadastro.php

  1. isset($_POST['excluir']) pergunta "clicaram em Excluir?". Esse teste vem antes do cadastro.
  2. (int) garante que o valor é um número inteiro.

banco.php

  1. excluirCliente() é o D do CRUD: DELETE ... WHERE id = :id.
  2. Cuidado: sem o WHERE, o DELETE apaga todos os clientes.

Funcionou? Envie para o GitHub: Add file › Upload files, arraste os três arquivos .php, escreva Versão 3: excluir e clique em Commit changes.

Para fechar

Faxina: apague o que não usamos mais

O Mini Cadastro não usa mais os arquivos das aulas anteriores. Se eles ficam na pasta, confundem. Fez a aula 11? Apague estes:

  • Cliente.php, clientes.php, tela-cadastro.php e validar.php
  • teste-cliente.php
  • .gitignore: com o upload, quem escolhe o que sobe é você
  • o banco antigo, clientes.sqlite

Os outros (banco.php e cadastro.php) você já trocou pelos novos na versão 1.

Faça assim:

  1. Na pasta: no VS Code, clique com o botão direito no arquivo e escolha Excluir.
  2. No GitHub: abra o arquivo, clique nos ⋯ (no canto direito, em cima do código), escolha Delete file e clique em Commit changes. Um arquivo por vez.
  3. Confira: a pasta tem só os arquivos abaixo. O GitHub tem os mesmos, menos o cadastro.sqlite.
1cadastro-clientes/2    index.html3    cadastro.php4    banco.php5    tela.php6    teste.php7    cadastro.sqlite   // só na pasta, nunca no GitHub

Apagou e se arrependeu? O GitHub guarda tudo no histórico (History). Nada se perde.

CU1 · caso de uso

PHP2Shell: o Apache do XAMPP na mira

Caso real, de outubro de 2026. As fontes estão no fim da seção.

Ator: Estudante com o XAMPP no notebook

Objetivo: Programar em PHP sem deixar o computador aberto para ataques.

Fluxo principal

  1. Antes de começar, abre o teste.php e confere a versão do PHP.
  2. Se estiver desatualizada, baixa o XAMPP novo no site oficial.
  3. Liga o Apache só enquanto está programando e desliga no fim.

E se...

  • O XAMPP é antigo? Em 21/10/2026, o PHP corrigiu duas falhas críticas, o PHP2Shell. Com elas, alguém de fora roda comandos no servidor sem precisar de senha. Já havia ataques desde 17/10, antes da correção.
  • O PHP roda dentro do Apache (o mod_php, que é como o XAMPP funciona)? Esse é apontado como o caso de maior risco.
  • Não dá para atualizar já? A orientação oficial é tirar o sistema do ar até corrigir.

Para pensar

  1. Por que o XAMPP é para desenvolver no seu computador, e nunca para servir um site na internet?
  2. Em 2024, outra falha (CVE-2024-4577) atingiu justamente o XAMPP no Windows e foi usada para espalhar ransomware. O que as duas histórias ensinam sobre atualizar?
  3. A correção saiu em 21/10, mas os ataques começaram em 17/10. O que isso diz sobre esperar para atualizar?

Fontes: CISA, alerta de 21/10/2026 · Tenable, perguntas frequentes · XAMPP, versões corrigidas · Help Net Security, CVE-2024-4577 (2024)
