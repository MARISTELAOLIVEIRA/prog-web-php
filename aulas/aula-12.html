Mini Loja com SQLite

Quatro arquivos, um banco que nasce sozinho e o CRUD completo de produtos.

Objetivo do dia

Montar a Mini Loja: listar, cadastrar, excluir e editar produtos num banco SQLite, com o PHP no Apache do XAMPP.

Antes da aula

Ter o XAMPP. Não precisa ter terminado as aulas anteriores: o projeto recomeça do zero.

Como conta ponto

Atividade no laboratório, enviada ao GitHub por upload.

P1 · o problema

Arquivo demais, cabeça de menos

O cadastro de clientes tinha arquivo para todo lado, e ficou difícil saber onde mexer. Hoje a gente recomeça pequeno, com uma loja de componentes eletrônicos: a Mini Loja. São quatro arquivos e um banco de verdade. Quem perdeu aulas começa junto, do zero.

Começamos pelo mais simples: produtos, só com nome e preço. A loja cresce no ritmo da turma: clientes, conferência dos dados e login entram nas próximas aulas, sempre nos mesmos quatro arquivos.

C1–C3 · conceitos

Três ideias, e só

C1

Quatro arquivos, cada um com um trabalho

É o MVC do restaurante, só que enxuto. Cada arquivo faz uma coisa só: deu problema, você já sabe onde procurar.

  • index.html: a porta da loja. Só HTML.
  • cadastro.php: o garçom (controle). Recebe o pedido e leva a resposta.
  • banco.php: a cozinha (modelo). O único que fala com o banco.
  • tela.php: o prato (visão). Só mostra.

O caminho de um clique: você abre o cadastro.php → ele pede os produtos ao banco.php → recebe a lista → entrega para a tela.php mostrar.

1mini-loja/2    index.html          // a porta: a página inicial3    cadastro.php        // o garçom: o controle4    banco.php           // a cozinha: o modelo (todo o SQL)5    tela.php            // o prato: a visão (o HTML)6    teste.php           // confere o ambiente7    mini-loja.sqlite    // o banco: nasce sozinho
C2

O SQL do CRUD

O banco é uma tabela, como uma planilha: cada linha é um produto, cada coluna é um dado (id, nome, preco).

CRUD são as quatro coisas que todo sistema faz com os dados: Criar, Ler (Read), Atualizar (Update) e Apagar (Delete). Hoje você usa as quatro, e todas moram no banco.php.

Repare: no SQL, o preço usa ponto (39.90), como na calculadora.

1// C: cria (cadastra) um produto2INSERT INTO produtos (nome, preco) VALUES ('Placa ESP32', 39.90)3// R: lê (lista) os produtos4SELECT id, nome, preco FROM produtos ORDER BY nome5// U: atualiza (edita) o produto de id 16UPDATE produtos SET preco = 42.50 WHERE id = 17// D: apaga (exclui) o produto de id 18DELETE FROM produtos WHERE id = 1
C3

prepare: o dado vai separado do comando

Nunca cole o que o usuário digitou dentro do SQL. Com o prepare, o comando vai com um marcador (:nome) e o dado vai separado, no execute.

Por quê? Sem o prepare, alguém digita um pedaço de SQL no formulário e o banco obedece. Esse ataque se chama SQL injection.

1// 1. o comando, com os marcadores :nome e :preco2$stmt = $pdo->prepare('INSERT INTO produtos (nome, preco) VALUES (:nome, :preco)');34// 2. os dados, separados5$stmt->execute([':nome' => $nome, ':preco' => $preco]);

T1 · tutorial

Mão na massa: a Mini Loja em 4 versões

Cada versão é o projeto inteiro, pronto para copiar. Faça uma de cada vez: copie, salve, recarregue o navegador, leia o "entenda o código" e só depois passe para a próxima.

A meta de hoje: as 4 versões, o CRUD completo. Não deu tempo? Termine em casa: o passo a passo serve do zero, em qualquer computador com o XAMPP. E o seu projeto fica no GitHub: Code › Download ZIP e ele volta inteiro.

Antes de começar

Ligue o Apache e teste o ambiente

Faça assim:

  1. Abra o XAMPP Control Panel e clique em Start na linha do Apache. O MySQL não precisa: o SQLite é um arquivo.
  2. Crie a pasta C:\xampp\htdocs\mini-loja. É uma pasta nova: o projeto antigo fica de lado, e a faxina dele está no fim.
  3. Abra a pasta no VS Code (Arquivo › Abrir pasta) e crie o index.html e o teste.php com o código das abas.
  4. No navegador, abra http://localhost/mini-loja/teste.php.

Apareceu "SQLite: DESLIGADO"? É o problema mais comum quando entra o banco. Resolva assim:

  1. No XAMPP Control Panel, na linha do Apache, clique em Config › PHP (php.ini).
  2. Procure (Ctrl + F) por pdo_sqlite. Se a linha for ;extension=pdo_sqlite, apague o ; do começo. Faça o mesmo com ;extension=sqlite3.
  3. Salve, clique em Stop e depois em Start no Apache, e recarregue o teste.php.

Apareceu "versão antiga"? No laboratório é assim mesmo: os computadores são da faculdade e você não consegue atualizar. Dá para estudar normalmente; só clique em Stop no Apache no fim da aula. O porquê está em "Virou notícia", mais abaixo.

entenda o código

O que o teste.php confere

teste.php

  1. PHP_VERSION é a versão do PHP do seu XAMPP. O version_compare compara com a primeira versão que corrigiu o PHP2Shell (veja "Virou notícia").
  2. extension_loaded('pdo_sqlite') responde se o PHP sabe falar com o SQLite. Este precisa dar "ligado".
  3. Use este teste em qualquer computador, antes de começar.
GitHub por upload

Como enviar o projeto, sem comandos

Faça assim (uma vez agora, e depois de cada versão):

  1. Entre em github.com com a sua conta.
  2. Clique em New, dê o nome mini-loja, marque Public e clique em Create repository.
  3. No repositório vazio, clique no link uploading an existing file. Das próximas vezes, use Add file › Upload files.
  4. Arraste os arquivos da pasta para a página. Nunca arraste o mini-loja.sqlite: o banco fica só no seu computador.
  5. Em Commit changes, escreva uma mensagem curta do que mudou e clique no botão verde Commit changes.

Mandou um arquivo com o mesmo nome? O GitHub troca pelo novo e guarda o antigo no histórico (History). Nada se perde.

Envie agora o index.html e o teste.php, com a mensagem Página inicial e teste do ambiente.

Versão 1 · R de Read

O banco nasce e a lista aparece

O banco.php cria a tabela e põe três produtos de exemplo. O cadastro.php pede a lista e chama a tela.php.

Faça assim:

  1. Crie o banco.php, o cadastro.php e o tela.php com o código das abas.
  2. Abra http://localhost/mini-loja/ e clique em Ver os produtos: a placa ESP32, o Arduino e o sensor aparecem.
  3. Olhe a pasta: o arquivo mini-loja.sqlite apareceu sozinho. É o banco.
entenda o código

Versão 1, linha a linha

banco.php

  1. new PDO('sqlite:' . __DIR__ . '/mini-loja.sqlite') abre o banco. __DIR__ é a pasta deste arquivo. Se o mini-loja.sqlite não existe, o PHP cria.
  2. ERRMODE_EXCEPTION: se o SQL tiver um erro, o PHP mostra o erro em vez de ficar quieto.
  3. CREATE TABLE IF NOT EXISTS cria a tabela só na primeira vez. O id se numera sozinho (AUTOINCREMENT), e o preco é REAL: um número com casas decimais.
  4. COUNT(*) conta os produtos. Se der zero, o INSERT põe três de exemplo, para a lista não começar vazia.
  5. listarProdutos() faz o SELECT e devolve um array. Cada produto é um array com as chaves 'id', 'nome' e 'preco'.

cadastro.php

  1. require traz as funções do banco.php para cá.
  2. $produtos = listarProdutos();: o garçom pede a lista à cozinha.
  3. require __DIR__ . '/tela.php' chama a visão. Ela enxerga a variável $produtos.

tela.php

  1. <?= ... ?> é o atalho de <?php echo ... ?>: escreve um valor no meio do HTML.
  2. count($produtos) mostra quantos produtos há.
  3. foreach ($produtos as $item) repete o <li> uma vez para cada produto. A cada volta, $item é o produto da vez.
  4. number_format($item['preco'], 2, ',', '.') escreve o preço do jeito brasileiro: 39.9 vira 39,90.
  5. htmlspecialchars impede que um nome com código HTML bagunce a página. É segurança.

Funcionou? Envie para o GitHub: Add file › Upload files, arraste o banco.php, o cadastro.php e o tela.php, escreva Versão 1: lista de produtos e clique em Commit changes.

entenda o código

Versão 2, o que mudou

tela.php

  1. O <form method="post" action="cadastro.php"> envia os campos para o controle.
  2. O name de cada campo vira a chave no PHP: name="preco" chega como $_POST['preco'].
  3. type="number" step="0.01": o campo só aceita número, com centavos. O required não deixa enviar vazio. A conferência dos dados no PHP entra numa próxima aula.

cadastro.php

  1. $_SERVER['REQUEST_METHOD'] === 'POST' quer dizer "o formulário foi enviado". Abrir a página pelo link é GET, e aí nada é gravado.
  2. trim tira os espaços das pontas. O ?? '' evita erro se o campo não veio.
  3. (float) transforma o texto "14.90" em número.
  4. inserirProduto() grava, e o header('Location: cadastro.php') recarrega a página limpa. Assim, o F5 não cadastra o mesmo produto duas vezes. O exit para o PHP ali.

banco.php

  1. inserirProduto() é o C do CRUD: o INSERT com prepare e os dados separados, no execute (veja a C3).

Versão 3, o que mudou

tela.php

  1. Cada produto ganha um formulário pequeno, com um botão só.
  2. O botão tem name="excluir" e value igual ao id do produto. Clicou, chega $_POST['excluir'] com esse número.

cadastro.php

  1. isset($_POST['excluir']) pergunta "clicaram em Excluir?". Esse teste vem antes do cadastro.
  2. (int) garante que o valor é um número inteiro.

banco.php

  1. excluirProduto() é o D do CRUD: DELETE ... WHERE id = :id.
  2. Cuidado: sem o WHERE, o DELETE apaga todos os produtos.

Versão 4 · U de Update

Editar: o CRUD fica completo

Cada produto ganha o link Editar. O mesmo formulário serve para cadastrar e para editar: quem decide é o id escondido.

Faça assim:

  1. Troque os três arquivos .php.
  2. Clique em Editar na Placa ESP32: o formulário vem preenchido.
  3. Mude o preço para 42.50 e clique em Salvar alterações.
entenda o código

Versão 4, o que mudou

tela.php

  1. Cada produto ganha o link cadastro.php?editar=1. O número vai no próprio endereço e chega como $_GET['editar'].
  2. O mesmo formulário serve para os dois: com um $produto para editar, o título vira "Editar produto" e o botão, "Salvar alterações".
  3. <input type="hidden" name="id"> é um campo escondido: leva o id do produto junto. Vazio, é produto novo.
  4. value="..." preenche os campos com os dados atuais. O ?? '' deixa vazio quando não há produto.

cadastro.php

  1. isset($_GET['editar']): clicaram em Editar? Então buscarProduto() traz o produto para a tela.
  2. No envio do formulário, $id > 0 decide: tem id, é edição (atualizarProduto); não tem, é produto novo (inserirProduto).

banco.php

  1. buscarProduto() faz um SELECT com WHERE id e devolve um produto só. Não achou? Devolve null, e a tela mostra o formulário vazio.
  2. atualizarProduto() é o U do CRUD: UPDATE produtos SET nome = :nome, preco = :preco WHERE id = :id.
  3. Cuidado: sem o WHERE, o UPDATE muda todos os produtos.

N1 · virou notícia

O que aconteceu com o PHP?

Em outubro de 2026, o PHP foi parar no noticiário, com apelido e tudo: PHP2Shell. Se alguém da sua família perguntar, a explicação é esta.

sem tecnês

Pense num restaurante. O site é o salão, e o PHP é o cozinheiro: é ele que monta cada prato, ou seja, cada página que chega até você.

Descobriram que a cozinha tinha uma porta dos fundos destrancada. Por ela, um estranho entrava sem crachá e mandava o cozinheiro fazer o que quisesse: abrir a despensa, levar as receitas, fechar o restaurante.

Em tecnês: duas falhas deixavam um invasor rodar comandos no servidor, sem precisar de senha.

  1. Os ataques começam

    17/10

    Criminosos já usavam a porta antes de quase todo mundo saber que ela existia.

  2. A falha vem a público

    20/10

    O mundo fica sabendo, e ela ganha o apelido PHP2Shell.

  3. Sai o conserto

    21/10

    O PHP lança versões novas (8.5.12, 8.4.27, 8.3.36 e 8.2.35): é a fechadura nova. A agência de cibersegurança dos Estados Unidos (CISA) pede para atualizar já.

  4. Entra na lista dos ataques reais

    26/10

    A CISA põe as duas falhas na lista das que criminosos estão usando de verdade.

Por que virou notícia?

Porque o PHP está por trás de uma parte enorme dos sites do mundo, e a porta dava acesso total. O TechCrunch chegou a chamar o caso de "PHP-ocalypse".

E nós com isso?

  • O XAMPP do laboratório tem a versão antiga, e você não consegue atualizar: os computadores são da faculdade.
  • Para estudar, ligue o Apache só durante a aula e clique em Stop no fim. Porta fechada, ninguém entra.
  • No seu computador, quando puder, instale o XAMPP novo.
  • Site de verdade, na internet, nunca fica com a versão antiga. Atualizar é trocar a fechadura.

Fontes: CISA, 21/10/2026 · Tenable, perguntas frequentes · TechCrunch, 24/10/2026

CU1 · caso de uso

PHP2Shell: o Apache do XAMPP na mira

Caso real, de outubro de 2026. A história está em "Virou notícia", logo acima.

Ator: Estudante com o XAMPP no laboratório e em casa

Objetivo: Programar em PHP sem deixar o computador aberto para ataques.

Fluxo principal

  1. Antes de começar, abre o teste.php e confere a versão do PHP.
  2. No laboratório, liga o Apache só enquanto está programando e clica em Stop no fim.
  3. Em casa, no computador dele, instala o XAMPP novo.

E se...

  • Não dá para atualizar, como no laboratório? Estude com o Apache ligado só durante a aula e sem dados de verdade.
  • O PHP roda dentro do Apache (o mod_php, que é como o XAMPP funciona)? Esse é apontado como o caso de maior risco.
  • É um site de verdade, na internet? Atualizar já. Sem dar, a orientação oficial é tirar do ar até corrigir.

Para pensar

  1. Por que o XAMPP é para desenvolver no seu computador, e nunca para servir um site na internet?
  2. Em 2024, outra falha (CVE-2024-4577) atingiu justamente o XAMPP no Windows e foi usada para espalhar ransomware. O que as duas histórias ensinam sobre atualizar?
  3. A correção saiu em 21/10, mas os ataques começaram em 17/10. O que isso diz sobre esperar para atualizar?

S1 · conexão STEAM

Cada peça no seu lugar

E

Eletrônica

Os produtos de exemplo são peças de verdade: o ESP32 e o Arduino são o "cérebro" de muitos projetos, e o DHT11 mede temperatura e umidade. Num circuito, o sensor mede, o microcontrolador decide e o display mostra. Na Mini Loja, o banco.php guarda, o cadastro.php decide e a tela.php mostra.

M

Matemática

No banco, o preço é REAL: um número com casas decimais. O number_format arredonda para duas casas (39.9 vira 39,90), e o ORDER BY põe tudo em ordem alfabética.

A

Arte

A tela.php é a única que cuida da aparência. Quer outra cara para a loja? Mexe só nela, e o resto continua funcionando.
