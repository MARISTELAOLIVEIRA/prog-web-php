Aula 9 Projeto Cadastro de Clientes, parte I

Onde vai parar o que o cliente digita?

Formulário com validação e o primeiro banco de dados do Cadastro de Clientes.

Objetivo do dia

Receber e validar os dados de um formulário com PHP e guardar cada cliente num banco de dados.

Antes da aula

Deixar o PHP rodando (XAMPP ou o servidor embutido do Lab-PHP) e revisar o $_POST.

Como conta ponto

Exercícios no laboratório, com commit no GitHub.

P1 · o problema

O cliente que sumiu

Você preenche o formulário, o PHP responde "Cadastro feito!" e, quando a página recarrega, o cliente sumiu. Não é bug: variável só vive enquanto a página está sendo montada.

Para o Cadastro de Clientes lembrar de alguém amanhã, os dados precisam de um lugar que não esquece. Hoje vocês fazem as duas coisas: um formulário caprichado, que confere tudo antes de aceitar, e o primeiro banco de dados do projeto.

C1–C8 · conceitos

Do formulário ao banco, em oito peças

C1

Cliente e servidor: quem pede e quem responde

Quando você digita maristelaoliveira.github.io, o seu navegador (o cliente) manda um pedido pela internet. Do outro lado, um computador do GitHub (o servidor) recebe, procura os arquivos e devolve o site. Toda página funciona assim: pedido e resposta.

Todo pedido leva um método, que diz o que o cliente quer. Os dois do dia a dia: GET ("me mostra") e POST ("toma, guarda isto").

Por que o PHP não roda no GitHub? O GitHub Pages só entrega arquivos prontos: HTML, CSS, JavaScript e imagens. Quem monta página com PHP é um servidor com PHP. No nosso cadastro, ele é o seu próprio computador, com php -S localhost:8000.

C2

O formulário certo

O method="post" manda os dados escondidos no corpo da requisição, e não no endereço. Cada campo precisa de um name: é por ele que o PHP encontra o valor. O id é do <label> e do CSS.

Pegadinha clássica: campo sem name não chega no PHP. Nem dá erro: simplesmente some.

1<form method="post">2  <label for="nome">Nome</label>3  <input id="nome" name="nome">45  <label for="email">E-mail</label>6  <input id="email" name="email" type="email">78  <label for="telefone">Telefone</label>9  <input id="telefone" name="telefone">1011  <button type="submit">Cadastrar</button>12</form>
C3

Receber e limpar

O PHP só processa quando o formulário foi enviado: é isso que o REQUEST_METHOD confere. Tudo chega dentro de $_POST, sempre como texto.

O trim() tira os espaços do começo e do fim, para ninguém passar na validação digitando só espaço.

1if ($_SERVER['REQUEST_METHOD'] === 'POST') {2    // ?? '' evita erro se o campo não vier3    $nome = trim($_POST['nome'] ?? '');4    $email = trim($_POST['email'] ?? '');5    $telefone = trim($_POST['telefone'] ?? '');6}
C4

Validar antes de usar

Dado de usuário é suspeito até prova em contrário. A função devolve uma lista de erros: lista vazia quer dizer que está tudo certo.

O filter_var() com FILTER_VALIDATE_EMAIL já sabe o formato de um e-mail. Não precisa inventar a regra.

1// recebe e confere os dados do formulário2function validarCliente(string $nome, string $email): array3{4    $erros = [];5    if (strlen($nome) < 3) {6        $erros[] = 'O nome precisa de pelo menos 3 letras.';7    }8    if (!filter_var($email, FILTER_VALIDATE_EMAIL)) {9        $erros[] = 'Digite um e-mail válido.';10    }11    return $erros;12}
C5

Errou? Não apague o que foi digitado

Quando der erro, a página volta com os campos preenchidos e o aviso na tela. Ninguém merece digitar tudo de novo.

Segurança: o htmlspecialchars() mostra o texto como texto. Sem ele, quem digitar <b> ou um <script> no nome muda a sua página.

1<input id="nome" name="nome"2       value="<?= htmlspecialchars($nome) ?>">34<?php foreach ($erros as $erro): ?>5  <p class="erro"><?= htmlspecialchars($erro) ?></p>6<?php endforeach; ?>
C6

Banco de dados: a memória que não esquece

Variável vive só enquanto a página está sendo montada. O banco guarda os dados num arquivo, e eles continuam lá amanhã.

Uma tabela é uma planilha com regras: cada coluna é um campo e cada linha é um cliente. O id numera as linhas sozinho, e o UNIQUE não deixa repetir e-mail.

Hoje a gente usa o SQLite, que já vem com o PHP: o banco é um arquivo, o clientes.sqlite. Mais à frente vem o MySQL, e o resto do código fica igual.

1// abre (ou cria) o arquivo do banco e a tabela de clientes2$pdo = new PDO('sqlite:' . __DIR__ . '/clientes.sqlite');3$pdo->setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION);45$pdo->exec('CREATE TABLE IF NOT EXISTS clientes (6    id INTEGER PRIMARY KEY AUTOINCREMENT,7    nome TEXT NOT NULL,8    email TEXT NOT NULL UNIQUE,9    telefone TEXT10)');1112// no MySQL do XAMPP, só a conexão muda:13// new PDO('mysql:host=localhost;dbname=loja;charset=utf8mb4', 'root', '');
C7

Gravar e listar com segurança

O prepare() monta o comando com marcadores (:nome, :email) e o execute() encaixa os valores. Assim o banco nunca confunde o que o usuário digitou com um comando.

Nunca cole $_POST direto dentro do SQL. Isso abre a porta para o ataque de SQL injection.

1$sql = 'INSERT INTO clientes (nome, email, telefone)2        VALUES (:nome, :email, :telefone)';3$stmt = $pdo->prepare($sql);4$stmt->execute([5    ':nome' => $nome,6    ':email' => $email,7    ':telefone' => $telefone,8]);910// e para listar:11$sql = 'SELECT nome, email FROM clientes ORDER BY nome';12$clientes = $pdo->query($sql)->fetchAll(PDO::FETCH_ASSOC);
C8

Cada arquivo com seu trabalho: o MVC

Num restaurante, o garçom não cozinha e a cozinheira não vai até a mesa. Cada um faz a sua parte, e por isso a casa funciona até lotada. No código é igual, e esse jeito de organizar tem nome: MVC, de Model, View, Controller (Modelo, Visão e Controle).

Modelo (clientes.php): o único que fala com o banco. Os comandos do C6 e do C7 moram lá, dentro de funções. Visão (tela-cadastro.php): só o HTML da página. Controle (cadastro.php): recebe o pedido, chama o modelo e mostra a visão.

Regra de ouro: SQL só no modelo, HTML só na visão. Achou um SELECT no meio do HTML? Alguém entrou na cozinha errada.

1// cadastro.php (o controle): só coordena2$erros = validarCliente($nome, $email);34if (!$erros) {5    inserirCliente($nome, $email);   // o modelo grava6}78$clientes = listarClientes();        // o modelo busca910require __DIR__ . '/tela-cadastro.php';  // a visão mostra

Para rodar: na pasta do projeto, abra o terminal e digite php -S localhost:8000. Depois abra http://localhost:8000/cadastro.php. No XAMPP, coloque a pasta dentro de htdocs.

T1 · tutorial

Mão na massa: o Cadastro de Clientes em 5 versões

Cada versão é o projeto inteiro, pronto para copiar. Faça uma de cada vez: copie, rode, teste, entenda o que mudou e só depois passe para a próxima. Aprender programação é isso: fazer, melhorar, acrescentar.

Antes de começar

Prepare a pasta e ligue o servidor

  1. Crie uma pasta chamada cadastro-clientes dentro do seu repositório.
  2. Abra a pasta no VS Code: Arquivo › Abrir pasta.
  3. Abra o terminal do VS Code (Terminal › Novo terminal) e ligue o servidor do PHP: php -S localhost:8000. No laboratório, use o PHP do XAMPP: C:\xampp\php\php.exe -S localhost:8000.
  4. No navegador, abra http://localhost:8000/cadastro.php.

Dica: deixe o servidor ligado o tempo todo. Mudou o código? Salve (Ctrl + S) e recarregue o navegador (F5). Para desligar, Ctrl + C no terminal.

Como copiar: clique na aba do arquivo, depois em Copiar. No VS Code, apague tudo o que tinha no arquivo (Ctrl + A e Delete), cole (Ctrl + V) e salve. A etiqueta de cada aba avisa: novo (crie o arquivo), mudou (troque o conteúdo todo) ou igual (não precisa mexer).

Versão 1

O formulário responde

Um arquivo só: o mesmo cadastro.php mostra o formulário e, quando ele é enviado, responde com o nome.

Faça assim:

  1. Crie o arquivo cadastro.php, cole o código e salve.
  2. Abra http://localhost:8000/cadastro.php no navegador.

Teste:

  1. Envie o formulário com o seu nome.
  2. Envie o formulário vazio. O que aparece? Por quê?
  3. No navegador, clique com o botão direito e escolha Exibir código-fonte. Procure o PHP: ele não está lá.
Agora é com você:
  • Acrescente o campo E-mail (<label> e <input name="email">) e mostre o e-mail na mensagem.
  • Troque o texto do botão de "Enviar" para "Cadastrar".
  • Se o nome vier vazio, mostre "Escreva o seu nome" em vez da saudação.

Funcionou? Guarde a versão: git add . e git commit -m "Versão 1: o formulário responde".

Versão 2

Valida e avisa

Agora o PHP confere os dados antes de aceitar. Os erros aparecem na tela e o que foi digitado continua nos campos.

Faça assim:

  1. Crie o arquivo validar.php e cole o código.
  2. Troque todo o conteúdo do cadastro.php pelo novo.
  3. Salve os dois e recarregue o navegador.

O que mudou: apareceu o arquivo validar.php, com a função que confere os dados. O cadastro.php chama essa função com require_once, mostra os erros e mantém os valores com value.

Teste:

  1. Envie "Al" no nome e "semarroba" no e-mail. Repare que os campos continuam preenchidos.
  2. Envie dados certos e veja a mensagem de sucesso.
  3. Digite <b>Oi</b> no nome. O texto aparece como texto, sem negrito: é o htmlspecialchars() trabalhando.
Agora é com você:
  • Acrescente o campo Telefone, que pode ficar vazio (não entra na validação).
  • Crie a regra: o nome pode ter no máximo 60 letras.
  • Coloque o erro de cada campo logo abaixo do campo, e não no topo.

Funcionou? Guarde a versão: git add . e git commit -m "Versão 2: validação com erros na tela".

Versão 3

Guarda no banco de dados

Chegou a hora do banco. Cada cliente vai para o arquivo clientes.sqlite e continua lá, mesmo se você fechar o navegador. E já do jeito certo: o SQL ganha um arquivo só dele, o modelo (veja o C8).

Faça assim:

  1. Crie o arquivo banco.php e cole o código. Ele abre o banco e, na primeira vez, cria o arquivo e a tabela sozinho: você não precisa criar nada antes.
  2. Crie o arquivo clientes.php (o modelo) e cole o código.
  3. Troque todo o conteúdo do cadastro.php pelo novo.
  4. Crie o arquivo .gitignore (com o ponto no começo) e cole o código.
  5. Salve tudo e recarregue o navegador. O arquivo clientes.sqlite aparece na pasta no primeiro acesso.

O que mudou: o banco.php tem a função conectar(). O clientes.php é o modelo, com as únicas funções que falam SQL: inserirCliente(), emailCadastrado() e listarClientes(). O cadastro.php não tem nenhum SQL: só chama essas funções, em passos numerados nos comentários. O .gitignore deixa o banco fora do GitHub. O validar.php não mudou.

Caminho de um cadastro: navegador → cadastro.php → validar.php → clientes.php → banco.php → clientes.sqlite

Teste:

  1. Cadastre dois clientes. Feche o navegador, abra de novo: eles continuam lá.
  2. Tente cadastrar de novo um e-mail que já existe.
  3. Procure SELECT ou INSERT no cadastro.php: não tem. Estão todos no clientes.php.
Agora é com você:
  • Mostre o total de clientes no título da lista, com count($clientes) (no cadastro.php, na parte do HTML).
  • No clientes.php, troque para ORDER BY id DESC: os mais novos aparecem primeiro. Repare que o cadastro.php nem ficou sabendo.
  • Acrescente a coluna Cidade, um arquivo de cada vez: a coluna na tabela (banco.php; depois apague o clientes.sqlite para a tabela nascer de novo), o INSERT e o SELECT (clientes.php) e o campo no formulário (cadastro.php).

Funcionou? Guarde a versão: git add . e git commit -m "Versão 3: clientes guardados no SQLite, com modelo".

Versão 4

Cada arquivo com seu trabalho

O cadastro.php ainda faz dois trabalhos: controla e mostra a página. Agora o HTML vai para um arquivo só dele, a visão, e o projeto fica no MVC completo. A página continua igualzinha: mudar a organização sem mudar o resultado tem nome, refatorar.

Faça assim:

  1. Crie o arquivo tela-cadastro.php (a visão) e cole o código.
  2. Troque todo o conteúdo do cadastro.php pelo novo: agora ele não tem HTML nenhum.
  3. Salve os dois e recarregue o navegador. Tudo funciona como antes.

O que mudou: apareceu o tela-cadastro.php, com todo o HTML que estava no cadastro.php. O cadastro.php ficou só com o PHP e termina chamando a tela com require. As variáveis que ele criou ($nome, $erros, $clientes...) continuam valendo na tela, porque o require cola o arquivo ali. Os outros arquivos não mudaram.

Caminho de um cadastro: navegador → cadastro.php → validar.php → clientes.php → banco.php → clientes.sqlite → de volta: cadastro.php → tela-cadastro.php → navegador

Versão 5

Busca e visual caprichado

O cadastro ganha busca e cara de sistema. Repare como cada mudança vai para o seu lugar: SQL no modelo, $_GET no controle, HTML e CSS na visão.

Faça assim:

  1. Troque todo o conteúdo do clientes.php, do cadastro.php e do tela-cadastro.php pelos novos.
  2. Crie o arquivo estilo.css e cole o código.
  3. Salve tudo e recarregue o navegador.

O que mudou: no modelo (clientes.php), a listarClientes() recebe um pedaço do nome e usa o LIKE do SQL, sempre com prepare(). No controle (cadastro.php), a busca chega pelo $_GET, porque ela fica no endereço: ?busca=ana. Na visão (tela-cadastro.php), entram o formulário de busca, o total de clientes e o link para o estilo.css. O banco.php e o validar.php não mudaram.

Teste:

  1. Cadastre uns quatro clientes e busque por um pedaço do nome.
  2. Repare no endereço da página depois da busca: o termo está lá. Copie o endereço e abra numa aba nova.
  3. Busque por uma letra que nenhum nome tem.
Agora é com você:
  • Quando a busca não achar ninguém, mostre "Nenhum cliente encontrado" (na visão).
  • Crie um link "Limpar busca", que volta para cadastro.php (na visão).
  • Já pensando na próxima aula: coloque um link "Editar" ao lado de cada cliente. O modelo vai precisar de duas funções novas, buscarCliente() e atualizarCliente(). A tela de edição vem no módulo 7 do curso.

Funcionou? Guarde a versão: git add . e git commit -m "Versão 5: busca e visual".

CU1 · caso de uso

Cadastrar um cliente

Ator: Atendente da loja

Objetivo: Cadastrar um cliente novo e ver o nome dele na lista.

Fluxo principal

  1. O atendente preenche nome, e-mail e telefone.
  2. O sistema confere os dados.
  3. Grava o cliente no banco.
  4. Mostra a confirmação e a lista atualizada.

E se...

  • O nome é curto ou o e-mail é inválido: o sistema avisa e mantém o que foi digitado.
  • O e-mail já está cadastrado: o sistema avisa e não grava duas vezes.

Para pensar

  1. Em que passo entra cada arquivo: cadastro.php (controle), validar.php, clientes.php (modelo), banco.php e tela-cadastro.php (visão)?
  2. O que acontece com os clientes se você fechar o navegador? E se apagar o clientes.sqlite?

S1 · conexão STEAM

Memória que não esquece

E

Eletrônica

Variável é como a memória RAM: some quando desliga. O banco é como o SSD: fica gravado. Num ESP32 é igual, e quem não salva na memória flash perde tudo quando a placa reinicia.

M

Matemática

Uma tabela é uma matriz: linhas vezes colunas. O id é a posição de cada linha, como o número de série de um componente.

A

Arte

O formulário é a vitrine do sistema. Rótulo claro, espaço entre os campos e erro escrito em português de gente fazem o cliente terminar o cadastro.

D1 · desafio extra

Terminou antes? Tem mais.

Coloque um campo de busca em cima da lista. Ele mostra só os clientes cujo nome contém o que foi digitado, com WHERE nome LIKE :busca e, claro, prepare(). Dica: o valor do marcador é '%' . $busca . '%'.
