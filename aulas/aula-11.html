Fac Senac DF Aula 11 Situação-problema Classes e objetos

Do array ao objeto

O cliente do Cadastro vira uma peça só: classe, atributos, métodos e private.

Objetivo do dia

Transformar o cliente do Cadastro em um objeto, com a classe Cliente, e comparar o código estruturado com o orientado a objetos.

Antes da aula

Deixar a versão 4 do Cadastro de Clientes (aula 9) rodando com o php -S.

Como conta ponto

Atividade no laboratório, com commit no GitHub.

P1 · o problema

O cliente de duas caras

No projeto, um arquivo usa $cliente['nome'] e outro usa $cliente['Nome']. O PHP não reclama: só mostra vazio. Com o sistema crescendo, cada pessoa escreve a chave de um jeito, e a regra de validar fica copiada em vários lugares.

Como garantir que todo cliente tenha sempre os mesmos dados e as mesmas regras? Hoje o cliente deixa de ser um array solto e vira um objeto: uma peça só, com os dados e as regras juntos.

C1–C7 · conceitos

Do array ao objeto, em sete peças

C1

Classe é o molde; objeto é a peça

A classe é o projeto: diz que dados todo cliente tem e o que ele sabe fazer. O objeto é um cliente de verdade, feito a partir desse projeto, com os dados dele.

É como uma placa de circuito: o projeto é um só, e cada placa fabricada é uma peça diferente. O new é a fábrica.

1// a classe: o molde (um arquivo, Cliente.php)2class Cliente3{4    // os dados e as regras de todo cliente moram aqui5}67// os objetos: as peças, cada uma com os seus dados8$ana = new Cliente('Ana Souza', 'ana@email.com');9$bruno = new Cliente('Bruno Lima', 'bruno@email.com');
C2

Atributos e o construtor

Os atributos são os dados do objeto: nome, e-mail. O construtor, __construct, roda sozinho no new e preenche esses dados.

No PHP 8, dá para criar e preencher o atributo direto nos parênteses do construtor: é a promoção de propriedades. Menos código, o mesmo resultado.

Nome de arquivo: uma classe por arquivo, com o nome da classe e a primeira letra maiúscula: Cliente.php.

1class Cliente2{3    // promoção de propriedades: o atributo nasce aqui mesmo4    public function __construct(5        public string $nome,6        public string $email7    ) {8    }9}1011$ana = new Cliente('Ana Souza', 'ana@email.com');12echo $ana->nome;   // Ana Souza
C3

Métodos, $this e a setinha ->

Método é uma função que mora dentro da classe. Dentro dele, $this quer dizer "este objeto aqui": é assim que o método acha os dados do próprio cliente.

A setinha -> chama o atributo ou o método de um objeto: $ana->nome, $ana->primeiroNome().

1class Cliente2{3    // ... o construtor da C2 ...45    // "Ana Souza" vira "Ana"6    public function primeiroNome(): string7    {8        return explode(' ', trim($this->nome))[0];9    }10}1112$ana = new Cliente('Ana Souza', 'ana@email.com');13echo 'Olá, ' . $ana->primeiroNome();   // Olá, Ana
C4

public e private: quem pode mexer

public qualquer arquivo lê e muda. private só a própria classe mexe: por fora, só pelos métodos dela. É assim que a regra fica num lugar só.

O telefone é private: a classe guarda só os números e entrega formatado. Ninguém grava "(61) 9-9599" torto por engano.

Tentou ler de fora? O PHP para tudo com Cannot access private property. Não é bug: é a proteção funcionando.

1class Cliente2{3    private string $telefone;   // só a classe mexe45    public function telefoneFormatado(): string6    {7        // a regra de formatar mora aqui, e só aqui8    }9}1011echo $ana->telefoneFormatado();   // (61) 99599-351312echo $ana->telefone;              // erro: é private
C5

Do array ao objeto

Com array, cada arquivo escreve a chave do seu jeito: 'nome' num lugar, 'Nome' no outro, e ninguém avisa. Com objeto, a classe define os nomes, e o VS Code até sugere enquanto você digita.

Errou o nome do atributo? O PHP avisa na hora, em vez de deixar o dado sumir em silêncio.

1// estruturado: um array, e cada um escreve a chave como quer2$cliente = ['nome' => 'Ana Souza', 'email' => 'ana@email.com'];3echo $cliente['Nome'];     // vazio: chave escrita diferente45// orientado a objetos: a classe manda nos nomes6$cliente = new Cliente('Ana Souza', 'ana@email.com');7echo $cliente->nome;       // Ana Souza8echo $cliente->Nome;       // aviso: esse atributo não existe
C6

Onde a classe mora no MVC

A classe Cliente faz parte do modelo: é a ficha técnica do prato, que a cozinha segue. O garçom (controle) monta o pedido com new Cliente(...); a cozinha (clientes.php) grava e devolve objetos; o prato (a visão) só mostra.

O validar.php some: a validação virou o método validar(), junto dos dados que ela confere.

1// cadastro.php (controle)2$cliente = new Cliente($nome, $email);3$erros = $cliente->validar();4inserirCliente($cliente);56// clientes.php (modelo): recebe e devolve objetos7function inserirCliente(Cliente $cliente): void { /* ... */ }89// tela-cadastro.php (visão)10echo $cliente->primeiroNome();
C7

GitHub: cada versão é um commit

Refatorar é mudar o código sem mudar o que ele faz. Com um commit por versão, dá para voltar atrás se algo quebrar e mostrar, no GitHub, como o projeto evoluiu.

O git status mostra o que mudou, até o validar.php apagado. A mensagem do commit conta o que foi feito: "Versão 2: cadastro com objetos" diz muito mais que "ajustes".

Lembrete: o clientes.sqlite continua no .gitignore. Dado de cliente não vai para o GitHub.

1git status   # o que mudou desde o último commit23deleted:    validar.php   # o arquivo apagado também aparece4new file:   Cliente.php56git add .   # junta tudo, até o que foi apagado7git commit -m "Versão 2: cadastro com objetos"8git log --oneline   # a história do projeto, uma linha por versão9git push   # manda as versões para o GitHub

T1 · tutorial

Mão na massa: o cliente vira objeto em 3 versões

Cada versão é o projeto inteiro, pronto para copiar. Faça uma de cada vez: copie, rode, teste, entenda o que mudou e só depois passe para a próxima.

O combinado de hoje: as versões 1 e 2 na aula. A versão 3 (telefone e private) é para quem terminar antes ou para casa.

Antes de começar

O ponto de partida é a versão 4 da aula 9

  1. Abra a pasta cadastro-clientes no VS Code. Não terminou a versão 4? Copie da aula 9.
  2. Ligue o servidor no terminal do VS Code: php -S localhost:8000. No laboratório: C:\xampp\php\php.exe -S localhost:8000.
  3. Confira se http://localhost:8000/cadastro.php abre e cadastra.
  4. Rode git status: tem que aparecer "nothing to commit". Se aparecer arquivo mudado, faça o commit antes de começar.
Versão 1

O molde: a classe Cliente, testada sozinha

Antes de mexer no cadastro, a classe nasce num arquivo só e é testada numa página de teste. Se der erro, o erro está na classe, e não no cadastro inteiro.

Faça assim:

  1. Crie o arquivo Cliente.php (com C maiúsculo), cole o código e salve.
  2. Crie o teste-cliente.php, cole e salve.
  3. Abra http://localhost:8000/teste-cliente.php: a Ana passa sem erro e a Bi recebe os dois avisos.
  4. Brinque: troque os dados da Bi até ela passar sem erro.

Funcionou? Guarde e envie para o GitHub, um comando de cada vez:

1# 📦 1. põe na caixa2git add .3# 🏷️ 2. fecha e etiqueta4git commit -m "Versão 1: classe Cliente"5# 🚚 3. envia6git push

O git push reclamou? Se aparecer rejected, rode git pull e depois git push de novo. Se aparecer no upstream branch, rode uma vez git push -u origin main.

Versão 2

O cadastro usa objetos

Agora o controle monta um new Cliente(...), o próprio cliente se valida, o modelo grava e devolve objetos, e a visão troca $cliente['nome'] por $cliente->nome.

Faça assim:

  1. Troque o cadastro.php, o clientes.php e o tela-cadastro.php pelos da aba (as etiquetas "mudou" mostram quais).
  2. Apague o validar.php: a validação agora é o método validar() da classe.
  3. Cadastre alguém e veja a mensagem com o primeiro nome. Tente o mesmo e-mail de novo: o aviso continua.

Funcionou? Confira com git status (o validar.php aparece como apagado). Depois, guarde e envie para o GitHub, um comando de cada vez:

1# 📦 1. põe na caixa2git add .3# 🏷️ 2. fecha e etiqueta4git commit -m "Versão 2: cadastro com objetos"5# 🚚 3. envia6git push
Versão 3

Telefone protegido com private

O cliente ganha telefone. Ele é private: a classe guarda só os números e entrega formatado, com telefoneFormatado().

Faça assim:

  1. Troque o Cliente.php, o banco.php, o clientes.php, o cadastro.php e o tela-cadastro.php.
  2. Apague o arquivo clientes.sqlite: a tabela ganhou a coluna telefone e precisa nascer de novo. Os clientes de teste somem, e tudo bem.
  3. Cadastre com o telefone escrito de vários jeitos: (61) 99599-3513, 61995993513. Na lista, sai sempre igual.
  4. Experimente: no teste-cliente.php, escreva echo $ana->telefone; e veja o PHP proteger o dado.

CU1 · caso de uso

O array que cresceu demais

Caso fictício, criado para a aula.

Ator: Atendente de uma pequena empresa de entregas

Objetivo: Registrar um pedido com o endereço de entrega e calcular o frete.

Fluxo principal

  1. O atendente preenche o cliente, o endereço e o valor do pedido.
  2. O sistema confere os dados e calcula o frete (grátis acima de um valor).
  3. Grava o pedido.
  4. O entregador vê o pedido com o endereço na tela dele.

E se...

  • Cada programador escreveu a chave de um jeito (endereco, endereço, end_entrega): o entregador saiu com o endereço em branco.
  • A regra do frete grátis estava copiada em seis arquivos, cada uma diferente: o mesmo pedido pagava frete numa tela e não pagava na outra.

Para pensar

  1. Como uma classe Pedido evitaria as chaves diferentes?
  2. Onde a regra do frete deveria morar?
  3. Que dados do pedido deveriam ser private?

S1 · conexão STEAM

Encapsular é coisa de chip

E

Eletrônica

Um chip esconde os circuitos dentro do encapsulamento e deixa de fora só os pinos. A classe faz igual: o private é o circuito escondido, e os métodos public são os pinos.

M

Matemática

A classe é como a definição de um conjunto: diz o que todo elemento tem. Cada objeto é um elemento. E um método é uma função: entra um cliente, sai o primeiro nome.

A

Arte

Na arte com sucata, um molde gera várias peças, e cada uma ganha a sua cor e o seu acabamento. Mesmo molde, peças diferentes: classe e objetos.
