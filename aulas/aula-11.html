Mini Loja: arrays e formulário

Quatro arquivos, uma prateleira de produtos e um formulário. O banco fica para a próxima aula.

Objetivo do dia

Montar a vitrine da Mini Loja: os produtos num array, mostrados na tela, e um formulário que envia dados ao PHP.

Antes da aula

Ter o XAMPP. Não precisa ter terminado as aulas anteriores: o projeto começa do zero.

Como conta ponto

Atividade no laboratório, enviada ao GitHub por upload.

P1 · o problema

Toda loja começa pela vitrine

Uma loja de componentes eletrônicos quer mostrar os produtos na internet e cadastrar os que chegam. Hoje você monta a Mini Loja: quatro arquivos, cada um com um trabalho, sem banco e sem classe. Só arrays e um formulário.

A loja cresce no ritmo da turma: na aula 12 ela ganha um banco de dados, e depois vêm os clientes e o login. Sempre nos mesmos quatro arquivos.

C1–C3 · conceitos

Três ideias, e só

C1

Quatro arquivos, cada um com um trabalho

A Mini Loja segue o MVC da loja, só que enxuto. Cada arquivo faz uma coisa só: deu problema, você já sabe onde procurar.

  • index.html: a porta da loja. Só HTML.
  • cadastro.php: o vendedor (controle). Recebe o pedido e leva a resposta.
  • banco.php: o estoque (modelo). Guarda os dados.
  • tela.php: o balcão (visão). Só mostra.

O caminho de um clique: você abre o cadastro.php → ele pede os produtos ao banco.php → recebe a lista → entrega para a tela.php mostrar.

1mini-loja/2    index.html      // a porta: a página inicial3    cadastro.php    // o vendedor: o controle4    banco.php       // o estoque: o modelo (os dados)5    tela.php        // o balcão: a visão (o HTML)
C2

Array: a prateleira de produtos

Um produto é um array com chaves: cada dado tem um nome, como 'nome' e 'preco'.

A lista é um array de produtos, como uma prateleira. O foreach passa por ela, um produto de cada vez.

1// um produto: cada dado tem um nome (a chave)2$produto = ['nome' => 'Placa ESP32', 'preco' => 39.90];3echo $produto['nome'];   // Placa ESP3245// a prateleira: um array de produtos6$produtos = [7    ['nome' => 'Arduino Uno', 'preco' => 59.90],8    ['nome' => 'Placa ESP32', 'preco' => 39.90],9];1011// foreach: um produto de cada vez12foreach ($produtos as $item) {13    echo $item['nome'];14}
C3

Do formulário ao PHP

O formulário envia os campos para o cadastro.php. Cada campo tem um name, e ele vira a chave do $_POST.

Com method="post", os dados vão dentro do pedido, e não no endereço da página.

1// na tela.php, o campo tem um name:2//   <input name="nome">34// no cadastro.php, o dado chega no $_POST:5$nome = $_POST['nome'];

T1 · tutorial

Mão na massa: a Mini Loja em 3 versões

Cada versão é o projeto inteiro, pronto para copiar. Faça uma de cada vez: copie, salve, recarregue o navegador, leia o "entenda o código" e só depois passe para a próxima.

Para refazer em casa: este passo a passo serve do zero, em qualquer computador com o XAMPP. E o seu projeto fica no GitHub: Code › Download ZIP e ele volta inteiro.

Antes de começar

Ligue o Apache e crie a página inicial

Faça assim:

  1. Abra o XAMPP Control Panel e clique em Start na linha do Apache.
  2. Crie a pasta C:\xampp\htdocs\mini-loja. É uma pasta nova: o projeto antigo de clientes fica de lado (a faxina dele está na aula 12).
  3. Abra a pasta no VS Code (Arquivo › Abrir pasta) e crie o index.html com o código da aba.
  4. No navegador, abra http://localhost/mini-loja/. O index.html abre sozinho: o Apache procura por ele quando o endereço termina na pasta.

No fim da aula, clique em Stop no Apache. O XAMPP do laboratório tem uma versão antiga do PHP, e a aula 12 conta por quê.

GitHub por upload

Como enviar o projeto, sem comandos

Faça assim (uma vez agora, e depois de cada versão):

  1. Entre em github.com com a sua conta.
  2. Clique em New, dê o nome mini-loja, marque Public e clique em Create repository.
  3. No repositório vazio, clique no link uploading an existing file. Das próximas vezes, use Add file › Upload files.
  4. Arraste os arquivos da pasta para a página.
  5. Em Commit changes, escreva uma mensagem curta do que mudou e clique no botão verde Commit changes.

Mandou um arquivo com o mesmo nome? O GitHub troca pelo novo e guarda o antigo no histórico (History). Nada se perde.

Envie agora o index.html, com a mensagem Página inicial da Mini Loja.

Versão 1

A vitrine: a lista de produtos

O banco.php guarda três produtos num array. O cadastro.php pede a lista e chama a tela.php.

Faça assim:

  1. Crie o banco.php, o cadastro.php e o tela.php com o código das abas.
  2. Abra http://localhost/mini-loja/ e clique em Ver os produtos: a placa ESP32, o Arduino e o sensor aparecem, com os preços.
entenda o código

Versão 1, linha a linha

banco.php

  1. function listarProdutos(): array cria uma função que devolve um array. O : array avisa o tipo do que volta.
  2. O return devolve a prateleira: três produtos, cada um com as chaves 'nome' e 'preco'.
  3. Na aula 12, só esta função muda: a lista passa a vir de um banco de dados.

cadastro.php

  1. require traz as funções do banco.php para cá.
  2. $produtos = listarProdutos();: o vendedor pede a lista ao estoque.
  3. require __DIR__ . '/tela.php' chama a visão. Ela enxerga a variável $produtos.

tela.php

  1. <?= ... ?> é o atalho de <?php echo ... ?>: escreve um valor no meio do HTML.
  2. count($produtos) mostra quantos produtos há.
  3. foreach ($produtos as $item) repete o <li> uma vez para cada produto. A cada volta, $item é o produto da vez.
  4. number_format($item['preco'], 2, ',', '.') escreve o preço do jeito brasileiro: 39.9 vira 39,90.
  5. htmlspecialchars impede que um nome com código HTML bagunce a página. É segurança.

Funcionou? Envie para o GitHub: Add file › Upload files, arraste o banco.php, o cadastro.php e o tela.php, escreva Versão 1: vitrine de produtos e clique em Commit changes.

Versão 2

O formulário chega ao PHP

A tela.php ganha o formulário. O cadastro.php recebe os dados e confirma o que chegou.

Faça assim:

  1. Troque o cadastro.php e a tela.php pelos das abas (a etiqueta "mudou" mostra quais).
  2. Envie o Sensor ultrassônico HC-SR04, por 14.90: aparece "Recebi: ...".
  3. Repare: ele ainda não entra na lista. Calma, é a versão 3.
entenda o código

Versão 2, o que mudou

tela.php

  1. O <form method="post" action="cadastro.php"> envia os campos para o controle.
  2. name="preco" chega no PHP como $_POST['preco'].
  3. type="number" step="0.01": o campo só aceita número, com centavos. O required não deixa enviar vazio.
  4. <?php if ($mensagem): ?> só mostra a mensagem quando ela existe.

cadastro.php

  1. $mensagem = '': a página começa sem mensagem.
  2. $_SERVER['REQUEST_METHOD'] === 'POST' quer dizer "o formulário foi enviado". Abrir a página pelo link é GET.
  3. trim tira os espaços das pontas. O ?? '' evita erro se o campo não veio.
  4. (float) transforma o texto "14.90" em número.
  5. O ponto (.) junta textos: 'Recebi: ' . $nome vira Recebi: Sensor....

Funcionou? Envie para o GitHub: Add file › Upload files, arraste o cadastro.php e a tela.php, escreva Versão 2: formulário e clique em Commit changes.

Versão 3

O produto entra na lista... e some

O produto enviado entra no fim do array e aparece na lista. Mas tem um mistério.

Faça assim:

  1. Troque o cadastro.php e a tela.php.
  2. Envie o sensor ultrassônico: a lista fica com 4 produtos.
  3. Clique em Ver a lista de novo. Sumiu!
  4. Envie um LED vermelho, por 0.50: só ele aparece, e o sensor não volta.
entenda o código

Versão 3, o que mudou (e por que sumiu)

cadastro.php

  1. $produtos[] = [...] coloca um produto novo no fim do array. Os colchetes vazios querem dizer "no próximo lugar livre".
  2. Por isso o listarProdutos() agora vem antes: primeiro a prateleira, depois o produto novo.

tela.php

  1. A mensagem ganhou o link Ver a lista de novo, que abre o cadastro.php sem enviar nada.

Por que o produto sumiu?

  1. O PHP tem memória curta. A cada pedido, ele começa do zero: lê os arquivos, monta a página, entrega e esquece tudo.
  2. O array $produtos só existe enquanto a página está sendo montada. Pedido novo, prateleira nova, de novo com 3 produtos.
  3. Para guardar de verdade, a loja precisa de um lugar que não esquece: um banco de dados. É a aula 12, e só o banco.php muda.

Funcionou? Envie para o GitHub: Add file › Upload files, arraste o cadastro.php e a tela.php, escreva Versão 3: o produto entra na lista e clique em Commit changes.

CU1 · caso de uso

O produto que sumiu da vitrine

Caso fictício, criado para a aula.

Ator: Dona de uma pequena loja de componentes eletrônicos

Objetivo: Mostrar os produtos com os preços e cadastrar os que chegaram.

Fluxo principal

  1. Abre a página da loja e vê a lista de produtos com os preços.
  2. Preenche o nome e o preço do produto que chegou.
  3. O produto aparece na lista.

E se...

  • Ela abre a página no dia seguinte e o produto não está lá? É a memória curta do PHP: falta um lugar para guardar.
  • O preço chega como "14,90", com vírgula? O (float) para na vírgula, e o sensor passa a custar R$ 14,00. O campo type="number" evita isso, porque envia com ponto.

Para pensar

  1. Por que a lista volta a ter só 3 produtos quando a página abre de novo?
  2. Onde a loja poderia guardar os produtos para eles não sumirem?
  3. Quando a lista vier de um banco de dados, qual dos quatro arquivos precisa mudar?

S1 · conexão STEAM

Memória que esquece, memória que guarda

E

Eletrônica

O Arduino tem dois tipos de memória: a RAM, que apaga quando ele desliga, e a EEPROM, que guarda. O array da versão 3 é como a RAM. Na aula 12, o banco de dados faz o papel da memória que guarda.

M

Matemática

A prateleira é uma tabela: cada produto é uma linha, cada chave é uma coluna. O count conta as linhas, e o number_format arredonda o preço para duas casas.

A

Arte

A tela.php é a única que cuida da aparência. Quer outra cara para a vitrine? Mexe só nela, e o resto continua funcionando.

D1 · desafio extra

Terminou antes? Tem mais.

Mostre embaixo da lista o valor total da vitrine, a soma dos preços. Dica: na tela.php, comece com $total = 0 e, dentro do foreach, vá somando $item['preco']. No fim, escreva o total com number_format.
